Scanner — UI ↔ API Integration Guide

Every screen element → its on-screen description → the API call → the request & response payload. Built for the UI team to bind fields directly. Modules: Endpoint · Cloud · Network · Database Connector · Code Repository.

✅ READY 🔵 NEW this round ⏳ PHASE 2

Conventions

  • Base URL (QA): https://qa-email.azure-api.net/qadlp · Auth: Authorization: Bearer <console JWT> (tenant read from token, never in body).
  • Envelope: every response is { "succeeded":true, "message":"", "data":<payload>, "errors":[] }. Below, the RESPONSE blocks show the data payload only.
  • Grids: request is QueryParameters { pageNumber, pageSize, searchTerm?, sortBy?, sortDescending?, exactFilters?, likeFilters? }; response data is { "TotalCount":N, "Data":[ …rows… ] }.
  • Evidence masked: sensitiveContent / maskedValue carry the match SHAPE only (AKIA••••7Q4D).
Two custody models (read the marker before showing actions): Platform-hosted → authMethod ∈ {AppKey, AdminConsent, ServiceAccount} → platform scans, "Scan now" allowed. Centralized / agent-hosted → authMethod="AgentHosted" (DB grid: source="Agent", signInStatus="ViaAgent") → the on-site EXE scans; no "Scan now". cloud/scans rejects agent-hosted, so it fails safe.
