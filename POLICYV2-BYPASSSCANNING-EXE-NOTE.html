Policy V2 · contract note for the exe / endpoint-agent team

A new bypassScanning flag on transfer exception rules

The server now accepts, stores and ships a per-exception-rule bypassScanning flag. The snapshot and the hash already carry it — the only new work is on the endpoint agent: honouring the flag at transfer time.

Where it is

Inside each exception rule object, in both transfer modules: modules.upload.exceptionGroups[].rules[] and modules.download.exceptionGroups[].rules[].

{
  "action": "Allow",
  "bypassScanning": true,
  ...
}

Always present on every exception rule (default false); only ever true on an Allow rule — the server rejects true on Warn/Block/step rules with 400 PV2_MODULE_INVALID. It rides the rule's raw JSON, so your parser passes it through unchanged.

Served by

GET {BaseUrl}/V2/PolicySnapshot/{endpointUserId} — the full policy; the flag sits in the rule objects above.

GET {BaseUrl}/V2/PolicyCheck/{endpointUserId}?hash=… — staleness check, unchanged.

Agent behaviour to implement

ModuleMatchDo
UploadAllow exception, bypassScanning:trueLet the upload through with no content scanning and do not log it.
DownloadAllow exception, bypassScanning:trueDo not log it. (An Allow already skips scanning on download, so the flag only changes logging here.)
Anything else (false, or Warn/Block/step rules)Unchanged behaviour.

Sync — no forced refresh needed

✓
Toggling the flag and publishing changes PublishedSnapshotHash (the hash is computed over the whole snapshot document, which now carries bypassScanning). So PolicyCheck returns updated on the agent's next poll and it refetches the snapshot the normal way — the tray Sync button is not required.

Server side — nothing to change

The exe API (PolicySnapshot / PolicyCheck) already passes the field and the moved hash through verbatim. Storage is the existing jsonb policy document — no migration, no schemaVersion bump. The only enforcement that lives outside the server is the agent behaviour in the table above.
