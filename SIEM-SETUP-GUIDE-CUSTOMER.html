Connecting Defensely to your SIEM

A guide for the engineer who runs your SIEM. There are two ways to connect, and you only need one. Set it up once; it runs by itself.

A · We push to your SIEM (Destinations)

In Defensely: Settings → Connectors → SIEM → Connect a SIEM. Pick your vendor, paste the credentials below, choose which events and which format, send a test, then switch it on. Nothing you pick here is irreversible — a destination is Paused until you enable it, and only enables after a test passes.

Splunk — HTTP Event Collector (~5 min)

  1. Settings → Data Inputs → HTTP Event Collector. Global Settings: All Tokens = Enabled, keep SSL on.
  2. New Token → name it Defensely DLP → choose an index → Submit → copy the Token Value.
  3. In Defensely paste the Collector URL (public host; port 443 / 8088 / 9243) and the HEC Token. Splunk Cloud uses https://http-inputs-<stack>.splunkcloud.com:443 — the wrong host is the usual mistake.

Microsoft Sentinel — Logs Ingestion API (~20 min)

  1. Create a Data Collection Endpoint (DCE) and a Data Collection Rule (DCR) with a custom stream (e.g. Custom-Defensely_CL).
  2. Register an app; grant it Monitoring Metrics Publisher on the DCR.
  3. In Defensely enter the DCE URL, the app's Tenant ID / Client ID / Client Secret, the DCR Immutable ID (DCR → JSON view → immutableId) and the Stream Name.

IBM QRadar — syslog over TLS (~10 min)

  1. Add a log source of type Universal LEEF with the TLS Syslog protocol on port 6514.
  2. In Defensely enter the host as qradar.acme.com:6514. No secret — TLS authenticates the server to us. Paste your private CA certificate only if QRadar uses one.

Generic HTTPS webhook (~2 min)

Any endpoint that accepts an HTTPS POST with a JSON body. Paste the URL and a bearer token (sent as Authorization: Bearer …, or a custom header name you choose).

What to send (same for every destination)

  • Filter — severity (Critical / High / Medium / Low) and event types. Splunk and Sentinel bill by data ingested, so send only what your team acts on.
  • Format — JSON (works with most tools) or CEF (ArcSight-style parsers). QRadar uses LEEF automatically.
  • Sensitive content — matched values (actual card/ID numbers) never leave Defensely. You choose between sending nothing about what matched (default) or a category summary; the raw value is never an option.

B · You pull from our API (API access)

In Defensely: Settings → Connectors → SIEM → Create API access. Name it, optionally restrict it to your collector's egress IPs, then copy the four values it shows (the secret is shown once). The feed works behind a firewall — your collector makes only outbound HTTPS.

What you get
Client IDsiem_…
Client secretshown once — store it in your secrets manager
Token URLhttps://api.defensely.ai/dlp/oauth/token
Events URLhttps://api.defensely.ai/dlp/siem/events

If you set Allowed IP ranges, a token is only issued to those addresses — make sure your collector's egress IP is in the list.

B.1 · Authenticate — OAuth 2.0 client credentials

curl -s https://api.defensely.ai/dlp/oauth/token \
  -d grant_type=client_credentials \
  -d client_id=$CLIENT_ID \
  -d client_secret=$CLIENT_SECRET \
  -d scope=siem:events.read

# → { "access_token": "…", "token_type": "Bearer", "expires_in": 3600, "scope": "siem:events.read" }

Cache the token until it expires; re-request on 401.

B.2 · Pull the event feed

curl -s "https://api.defensely.ai/dlp/siem/events?limit=500&format=json" \
  -H "Authorization: Bearer $ACCESS_TOKEN"

# → { "events": [ … ], "next_cursor": "…", "has_more": true, "schema_version": 1 }
  • Page forward with cursor=<next_cursor> until has_more is false; persist the last next_cursor and resume from it next poll.
  • First run may use from= (UTC ISO-8601) to backfill; after that, use the cursor.
  • format = json (default), ecs (Elastic Common Schema), cef or leef (returned as text/plain, one event per line, cursor in X-Next-Cursor).
  • limit up to the server max; poll every 30–60 s.

B.3 · Splunk — REST API Modular Input (paste-ready)

[rest://defensely_dlp]
endpoint = https://api.defensely.ai/dlp/siem/events
auth_type = oauth2_client_credentials
oauth2_token_url = https://api.defensely.ai/dlp/oauth/token
oauth2_client_id = <CLIENT_ID>
oauth2_client_secret = <CLIENT_SECRET>
oauth2_scope = siem:events.read
http_method = GET
url_args = format=json&limit=500
response_type = json
json_response_array_path = events
pagination_cursor_path = next_cursor
pagination_request_arg = cursor
index = dlp
sourcetype = defensely:dlp
polling_interval = 60

B.4 · Elastic — Filebeat httpjson (paste-ready)

filebeat.inputs:
  - type: httpjson
    request.url: https://api.defensely.ai/dlp/siem/events?format=ecs&limit=500
    request.method: GET
    auth.oauth2:
      client.id: "${CLIENT_ID}"
      client.secret: "${CLIENT_SECRET}"
      token_url: https://api.defensely.ai/dlp/oauth/token
      scopes: ["siem:events.read"]
    response.split:
      target: body.events
    response.pagination:
      - set:
          target: url.params.cursor
          value: "[[.last_response.body.next_cursor]]"
          fail_on_template_error: true
    interval: 60s

Use format=ecs for Elastic so fields land on ECS names with no ingest pipeline.

B.5 · Microsoft Sentinel

Easiest is Option A (we push) via the Logs Ingestion API above. To pull instead, use a Codeless Connector / Logic App on a timer: OAuth to the token URL, GET the events URL, page on next_cursor, and post the events array to your DCR.

Event schema

One JSON object per event (format=json). The authoritative, versioned field list — including severity numbers and the deliberately excluded fields — is served live at GET /dlp/siem/field-map.

{
  "schema_version": 1,
  "event_id": "a1b2c3d4-…",              // stable — DEDUPE ON THIS
  "event_class": "BlockedTransfer",
  "time": "2026-11-21T09:14:03.511Z",
  "tenant_id": "…",
  "vendor": "Defensely", "product": "DLP",
  "user": { "name": "jsmith", "id": "…" },
  "host": { "name": "LAPTOP-01", "id": "…", "os": "Windows" },
  "file": { "name": "Payroll.xlsx", "extension": ".xlsx", "size": 82400 },
  "destination": { "app": "Dropbox", "domain": "dropbox.com" },
  "dlp": {
    "transfer_type": "Upload", "content_type": "PFI",
    "policy": "Finance Upload", "action": "Block",
    "override_applied": false, "risk_score": 87
  },
  "event": { "severity": "High", "severity_num": 3 },
  "incident_url": "https://app.defensely.ai/incidents/…"
}
Matched values never leave Defensely. There is no field anywhere in this schema that carries the actual card number, ID or secret that was detected — only the file, user, policy, action and category.

Delivery guarantees & dedupe

  • The feed lags real time by ~30 seconds, on purpose. It guarantees an event is never skipped because it arrived while you were paging. Tell your SOC this, so the lag doesn't read as a fault.
  • At-least-once. An event can arrive twice (a retried poll, an overlap). Deduplicate on event_id — it is stable across redeliveries.
  • Ordering is by the cursor; always resume from the last next_cursor you stored.

Rotating the secret

Rotate an API-access secret from the console at any time. The old secret keeps working for 24 hours after rotation, so you can update your collector without an outage — then "End overlap now" once the new one is in place. A lost secret can't be recovered (not even by Defensely support); the only fix is to rotate.
