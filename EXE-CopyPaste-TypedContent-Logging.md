# Copy / Paste and Typed Content — how to log them

Handover to the EXE agent team.

**Marker legend.** **CODE** = established by reading the deployed implementation, cited by
file and line. **OPEN** = needs an answer from your side, or a query against a tenant
database. Nothing in this document was run against a database — the two queries at the end
are for whoever has access.

---

## The symptom

On the QA dashboard, Content Sharing reports:

| Channel | Events |
|---|---|
| Prompt | 880 |
| **Copy / Paste** | **0** |
| **Typed Content** | **0** |

Prompts work because they come from a different table entirely
(`dlp."AIPromptBlockLog"`, via `V1/InsertAIPromptLog`). Copy / Paste and Typed Content
come through the normal activity log, and **nothing is arriving under those two types**.

The dashboard is reporting accurately. The question is what the agent is sending.

---

## How an activity becomes a dashboard channel

**CODE.** The whole chain is one field. Nothing is inferred from content, clipboard APIs,
process names or URLs.

```
  AGENT
    │  POST V1/InsertLandLogV1   →   List<DlpLandinglogDTO>
    │  carries TransferTypeId : int          ← the only channel signal
    ▼
  dlp."LandingLog"                            raw row, keeps the id
    │
    │  crunch: id looked up in master."TransferTypeMaster"
    │          LandingLogRepository.cs:220-223, :361
    │          NOT FOUND  →  TransferTypeName = ""   (no error, no log)
    ▼
  crunch."LandingLogsCrunched"."TransferTypeName"    the NAME, denormalised
    │
    ▼
  dlp."vw_CombinedActivityLogs"."TransferTypeName"
    │
    ▼
  Dashboard  ChannelFor(name, isDevice)      DashboardV2Service.cs:2837-2863
             "Copy / Paste"  → copy_paste  → Content Sharing tab
             "Typed Content" → typed       → Content Sharing tab
```

So the dashboard matches on the **literal master-table name**. For an event to land on
Copy / Paste, `TransferTypeId` must point at a `master."TransferTypeMaster"` row named
exactly `Copy / Paste`.

## What the agent has to change, in one table

| | |
|---|---|
| **Changes** | Send `TransferTypeId` pointing at the `Copy / Paste` row for clipboard activity, and the `Typed Content` row for keyboard activity. Today neither appears to be sent — see the three candidate causes below. |
| **Changes** | Distinguish the two at capture time. The server cannot: nothing on the crunched row records whether content arrived via the clipboard or the keyboard, which is documented in `ActivityChannelResolver.cs:14-22`. If you can only tell us "not a file", we can only show one bucket. |
| **Unchanged** | The endpoint, the DTO, the auth, the batching. `V1/InsertLandLogV1` and `List<DlpLandinglogDTO>` are exactly as today. |
| **Unchanged** | Device transfers. Keep sending `Upload` / `Download` with `IsDevice = true` — the dashboard derives Device Write / Device Read from that pair. **Do not** switch to the `Device Write` / `Device Read` type names; the current convention is what is deployed and working. |
| **Unchanged** | AI prompts. They keep going to `V1/InsertAIPromptLog` and must not be duplicated here. |

## The blocker: `TransferTypeId` is not stable across tenants

**CODE.** This is the part that needs a decision before you hard-code anything.

The base template database ships five rows only — `bundle/master_dlp.data.sql:555-561`:

| Id | Name |
|---|---|
| 2 | All |
| 3 | Upload |
| 4 | Download |
| 5 | Send |
| 6 | Receive |

`Copy / Paste`, `Typed Content`, `Device Read`, `Device Write`, `Web Access` and
`Tenant Access` are **not in the template**. They are added by a migration,
`SeedActivityAndPolicyActionMasters.sql`, which must be run per tenant — and that
migration omits the id column, so **the database assigns it**. The column is
`GENERATED BY DEFAULT AS IDENTITY` (`master_dlp.schema.sql:3066`), so every tenant that
ran the seed could have got different ids depending on what was already in its table.

The migration flags this itself, at lines 12-15:

> *"the agent reports activities by TransferTypeId, so after running this, confirm the ids
> each tenant ended up with match what the agent sends — if the agent uses fixed ids, any
> mismatch must be reconciled with the EXE team before rollout."*

That was never closed out. It is the likeliest reason the two counts are zero.

### What we propose — ids pinned, on our side

The column is `GENERATED **BY DEFAULT**`, not `ALWAYS`, so explicit ids can be inserted.
We change the seed to assign reserved ids rather than letting the database pick, and
`setval` the sequence past them so a later auto-insert cannot collide. Then every tenant
agrees and you can hard-code:

| Id | Name |
|---|---|
| 7 | Copy / Paste |
| 8 | Typed Content |
| 9 | Device Read |
| 10 | Device Write |
| 11 | Web Access |
| 12 | Tenant Access |

Ids 2-6 stay exactly as they are. **We will not renumber anything that exists** —
`dlp."RuleApplicationMap"`, `RuleDeviceMap` and `RuleDomainMap` all have foreign keys onto
this table (`master_dlp.schema.sql:8510, 8590, 8630`), so moving a live id would silently
repoint policy rules.

**OPEN — two things we need from you before we cut this:**

1. **Does the agent already hard-code any TransferTypeId?** If so, which values, and for
   which activity types? If your build already assumes different numbers, we use yours
   rather than making you re-ship.
2. **Can you tell clipboard from keyboard at capture time?** If the answer is no, say so
   and we will collapse the design to a single "Typed or pasted" channel rather than
   leaving a permanently empty bucket on the dashboard.

**OPEN — on our side:** any tenant that already ran the seed may hold different ids. Those
need reconciling before a pinned build goes out. Query 1 below reports what a tenant
actually has.

## Field contract for one clipboard or typed event

`POST V1/InsertLandLogV1` · body `List<DlpLandinglogDTO>` · DTO at
`SFM.DLP.Application/DTOs/DlpLandinglogDTO.cs:109`.

| Field | Send | Why it matters |
|---|---|---|
| `TransferTypeId` | the `Copy / Paste` or `Typed Content` id | **The only channel signal.** Everything on the Content Sharing tab keys off the name this resolves to. |
| `EndpointUserId` | the endpoint user | Drives Top Users Sharing Sensitive Content and the drill-down Users count. |
| `ContentTypeId` | the detected classification | Drives the **Sensitive Data Detected** card. Without it the event is counted but contributes nothing to the data-type breakdown. |
| `PolicyActionMasterId` | Allow / Block / Warn | Drives Blocked counts, Response Outcome, and "Stopped %". |
| `AppDeviceName` | the destination application | The event's second line, and the app rankings. |
| `ReceivedTime` | capture time, UTC | Windows, the activity heat map and off-hours all read this. |
| `SensitiveContent` | the matched identifiers | Feeds the classification breakdown. **Never send the matched values themselves** — identifier names only. |
| `ProcessName` | the host process | Useful on the event detail; not used for classification. |

### Fields that will misfile the event if you set them

These are the traps. Each one is a real code path, not a hypothetical.

| Field | If you set it | Consequence |
|---|---|---|
| `FileFullPath` | non-empty | The dashboard titles the row with the **file name** instead of the content type (`DashboardV2Service.cs:2696-2698`), and `ActivityChannelResolver` stops treating it as content. Send null or empty. |
| `FileSize` | non-null | The bytes are counted into **Data Classification "Volume Scanned"** and into **Exfiltration Attempts** (`ClassifyAsync` filters `FileSize != null`). If pasted text is not meant to register as transferred volume, send null. **OPEN — your call, but make it deliberately.** |
| `PromptContent` | non-empty | `ActivityChannelResolver.Resolve` returns `AiPrompt` for any row with prompt content (`ActivityChannelResolver.cs:84-85`), so the tray app will show a paste as an AI prompt. Leave it null. |
| `Url` | set, with no file | The same resolver returns `WebAccess` (`:92-93`). Only set `Url` when the content genuinely went to a website. |
| `IsDevice` | `true` | Forces the event onto Device Write / Device Read regardless of its transfer type (`ChannelFor`, `:2841-2850`). Must stay `false` for clipboard and keyboard events. |

## The silent-failure path you should know about

**CODE.** When `TransferTypeId` does not match a master row, the crunch does not reject
the row and does not log a warning. It writes **empty string** into `TransferTypeName`
(`LandingLogRepository.cs:361`):

```csharp
TransferTypeName = transferTypes.TryGetValue((short)log.TransferTypeId, out var tt) ? tt : string.Empty,
```

That row then behaves asymmetrically on the dashboard. `InArea` matches against the known
file and content type names, so an empty name belongs to **neither** area — the event
appears on **no tab and in no area card**. But Total Incidents, Policy Compliance,
Off-Hour Activity, the heat map and High-Risk Users all read the unscoped population, so
**they do count it**.

So a wrong id does not produce an error anyone will see. It produces a dashboard whose
headline figures cannot be reconciled against its tabs, with nothing on screen explaining
the gap. If you ship a build with an id we have not reconciled, this is how it will
present.

## How to verify, once a build sends the new types

1. Trigger a clipboard event and a typed event on a monitored endpoint.
2. Confirm the Content Sharing tab's **Copy / Paste** and **Typed Content** tiles move, and
   that the three channel tiles still sum to Total Content Events.
3. Confirm the event appears in the drill-down panel with the channel on its second line —
   `User · Copy / Paste · <app>` — and **not** as an Upload.
4. Confirm it did **not** add volume to Data Classification unless you intended `FileSize`.
5. Confirm the Overview's Total Incidents still reconciles against the three tabs. A gap
   means ids are not resolving — see the silent-failure path above.

### Two queries to settle where we are today

For whoever has QA database access. Neither has been run.

```sql
-- 1. Which transfer types exist on this tenant, and what ids did they get?
SELECT "TransferTypeMasterId", "TransferTypeName", "IsActive"
FROM   master."TransferTypeMaster"
ORDER  BY "TransferTypeMasterId";
```

If `Copy / Paste` and `Typed Content` are absent, the seed migration has not been run here
and that alone explains the zeros.

```sql
-- 2. What is actually landing, and is anything failing to resolve?
SELECT COALESCE(NULLIF("TransferTypeName", ''), '(unresolved)') AS transfer_type,
       COUNT(*)
FROM   crunch."LandingLogsCrunched"
WHERE  "ReceivedTime" >= NOW() - INTERVAL '7 days'
GROUP  BY 1
ORDER  BY 2 DESC;
```

An `(unresolved)` bucket means the agent is sending ids this tenant does not have — the
reconciliation problem, and the rows are currently invisible on every tab.
