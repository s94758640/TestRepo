Service Control — API for the console

Stop / Start / Restart DLPService on an endpoint from the admin console · three endpoints, one of them polled · 23 Nov 2026
The shape of it The console never talks to the endpoint. It posts a command to us, we push it to the endpoint's agent over a socket we already hold, and the agent reports back. You poll one endpoint until the command reaches a final state — normally within ten seconds.

There is no websocket for you. That is between us and the agent. Your side is three ordinary REST calls.

1. The flow

screen loads   GET  /api/endpoints/{serial}/push-status     → is the endpoint reachable?

admin clicks   POST /api/endpoints/{serial}/service-command → 202 { commandId, state }

every 1s       GET  /api/service-commands/{commandId}       → until state is final
                                                              (cap it, see §5)
AuthYour existing console JWT, plus the ClientGUID header you already send. Admin role required on all three — a read-only role gets 403
CasingcamelCase in and out
serialThe endpoint's serial as you already display it. Compared case-insensitively

2. Send a command

POST/api/endpoints/{serial}/service-command

{ "action": "Stop", "persist": true }
FieldTypeNotes
actionstring Stop | Start | Restart. Case-insensitive — "stop" is fine. Anything else is 400
persistbool, default true Stop only. true also disables the service's start type so it stays off after a reboot. Ignored for Start and Restart — we force it to false and the response shows that

202 Accepted, with Location: /api/service-commands/{commandId}

{
  "commandId": "47cb2222d24a4ca5b62d0f1190923fd1",
  "serial": "PW0F6X3B",
  "action": "Stop",
  "state": "Delivered",
  "endpointConnected": true,
  "finalStatus": null,
  "startType": null,
  "elapsedMs": null,
  "message": null,
  "createdAt": "2026-11-23T10:15:02.113+00:00",
  "completedAt": null
}
The "off" toggle means persist: true An admin turning DLP off expects it to stay off across a reboot, which is what persist does. Send false only for a one-time stop that comes back on restart. If your UI has a single on/off toggle, it is persist: true.

Errors

400Unknown action, or a serial over 128 characters
401No token
403Signed in, but not an admin role
404No active endpoint with that serial in this tenant

3. Poll for the result

GET/api/service-commands/{commandId} → 200 (same body as above) or 404

Call it every second until state is final.

stateMeaningWhat to show
Pending Saved; the endpoint is offline or we have not pushed it yet With endpointConnected:false this is not an error — see the box below
DeliveredSent to the endpoint Spinner on the toggle
AckedThe agent has it and is working Spinner
SucceededDone Move the toggle. finalStatus and startType are what the machine reported
FailedThe machine refused or timed out Revert the toggle and show message — it is the agent's own text, e.g. "Timed out waiting for the service to change state."
SupersededThe admin clicked again Drop this one silently; the newer command owns the toggle
ExpiredA stale Restart, never run "The endpoint came back too late — restart again if you still need it"

Final = Succeeded, Failed, Superseded, Expired. Stop polling on any of them.

4. Is the endpoint reachable?

GET/api/endpoints/{serial}/push-status

{ "serial": "PW0F6X3B", "connected": true }

Call it when the screen loads so the toggle can say online or offline before the admin clicks. It is cheap — an in-memory check, no database read.

connected:false does not disable the control. A command for an offline endpoint is saved and runs when the machine comes back; it is useful to tell the admin that in advance, not to stop them.

5. Four behaviours to build for

Offline is a normal outcome, not a failure state:"Pending" with endpointConnected:false means the command is stored and will be pushed the moment the endpoint reconnects — which could be minutes or days. Stop polling after about 60 seconds and leave the row in a "will apply when the endpoint comes online" state. Polling for hours achieves nothing.
A second click supersedes the first Only one command per endpoint is ever outstanding. If an admin clicks Stop and then Start before the first finishes, the Stop becomes Superseded and only the Start runs. Handle Superseded by ignoring that poll, not by showing an error — it is the system doing what the admin asked.
Disable the control while a command is open Not strictly required — the server is safe either way — but it keeps the toggle honest. Two rapid clicks produce two commands, and the first one's poll will come back Superseded, which looks like a glitch if the UI has already moved on.
Trust finalStatus, not the action you sent Succeeded means the command ran; finalStatus says what state the service actually ended in — Stopped, Running, and so on. A Stop that succeeds on an already-stopped service still reports Stopped. Drive the toggle from finalStatus and it will always match the machine.

6. Trying it before the agent exists

The endpoint agent build is not on QA endpoints yet. Until it is, these behave fully and are worth building against:

push-statusWorks now — reports connected:false for every endpoint until agents connect
POST …/service-commandWorks now — returns 202 with Pending and endpointConnected:false, exactly the offline path
GET …/service-commands/{id}Works now — stays Pending

So the whole offline flow, the supersede behaviour and every error case are testable today. What cannot happen yet is a command reaching Succeeded, because nothing is listening on the endpoint.

Swagger is switched off on QA The host only serves it when EnableSwagger is exactly "true", and that value lives in the local development settings, which QA does not load. If you want the Swagger UI on QA, it needs EnableSwagger=true adding as an app setting on the container app. Otherwise use the examples above directly — every call here is a plain REST request with your usual token and ClientGUID header.

The socket between the backend and the endpoint agent is documented separately in DLP-Service-Control-EXE-Handover.html; nothing there affects the console.
